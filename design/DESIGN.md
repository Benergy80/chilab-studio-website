# ChiLab Studio Design Contract

## Source

Reference template: `design-templates/neue-grafik-editorial/DESIGN.md`

Live reference: `https://chilabstudio.com`

Portfolio/image reference: existing local ChiLab project archive, Ben Stagl portfolio, Ally Reza portfolio, and the ChiLab Google Drive archive noted in `memory/chilab-drive-archive.md`.

## Position

ChiLab Studio is presented as a material problem-solving atelier for architecture, interiors, public art, fine art, and specialty fabrication.

The site should feel like a working project index from a serious studio: precise, dense, materially intelligent, and visually restrained.

## Layout

Use a five-column desktop grid.

Column 1 can carry numbers, index marks, and short facts.

Columns 2 to 4 carry the major title, prose, and project content.

Column 5 is the rail: contact, index counts, recognition, materials, credits.

Mobile collapses to one column. The rail follows the primary content.

## Type

Self-hosted Inter Tight is the project font. Use it hard:

- 900 weight for display.
- 700 for project names and important commands.
- 400 to 520 for body text.
- Letter spacing stays zero except small uppercase labels.

Avoid serif fallback ornament. ChiLab's material warmth comes from the work, not from type styling.

## Color

Use neutral paper, black ink, soft grey rules, and oxidized red for state and small accents.

No gradients. No glass effects. No pastel cream mood. No black luxury void.

## Imagery

Images must show the real work clearly. Prefer installed work, architectural context, material detail, and fabrication evidence.

The homepage should not use a generic shop atmosphere image as the whole hero. The work is the proof.

## Components

Masthead: five-column nav with direct text links.

Hero: oversized stacked title, short deck, dense rail.

Project ledger: a featured project image plus metadata, followed by standard project cards.

Work index: rows first, cards second. The preview panel on desktop makes the archive feel alive without hiding information.

Capability ledger: row-based, not card-based.

Project page: title, subtitle, lede, body, metadata rail, then image plates.

## Copy

Write plainly. Use workshop verbs: build, cast, finish, model, restore, install, coordinate.

Avoid inflated marketing language. No "elevate", "seamless", "revolutionize", or hype metrics.

## Motion

Only two patterns are allowed:

- Image preview changes on work index hover.
- Image contrast and saturation on work-card hover.

Reduced motion disables transitions.

## Future Edits

New pages should use the same shell, rail, rule, and ledger patterns.

Adding a new button or card variant requires updating `design/SYSTEM-SHEET.md` first.
